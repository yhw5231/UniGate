渠道固定

上游网关的一个模型可能内置多个上游渠道（如 Cline Pass 的 glm 背后随机路由到 alibaba/baseten 等）。这里为每个渠道的每个模型把请求钉到固定内部渠道： 严格固定按固定列表逐个独占尝试（注入 provider.only 或 providerOptions.gateway.only），固定优先注入完整 order 优先序。 「探测」发现该上游内置渠道清单并立即落盘，「验证」逐渠道测试；所有改动立即落盘生效。

编辑渠道

模型（勾选这个上游提供的模型；右侧「上游模型名」填上游认识的写法，留空 = 与对外名相同）

列表里存的是对外名（小写、去供应商前缀与 :free/-free 后缀，同一模型只暴露一个名字）， 发往上游用每行的「上游模型名」——上游写法自动写进 model_map； 同一对外名可以有多个上游写法（同一模型在上游的不同分组/线路各占一行，各自一个候选： 请求按顺序故障转移、冷却各自独立），对外仍然只有一个名字，路由页会逐行标注实际发往的上游名。 「添加」进「自定义」分组，行内填上游名即可配出**与上游名无关的渠道别名**（如 my-gpt → upstream/model-x）。 列表项支持精确名、通配（claude-* / gpt-4?）与正则（re:^gpt-4.*$）。 模型列表端点（/models）响应兼容 OpenAI 的 {"data":[...]}、裸数组、 以及按分组返回的 JSON（如 Cline 的 recommended-models：recommended/ free/clinePass/clineCloud，字段名即分组名）。
